# BrowserDock phase 3 implementation plan

**Goal:** Load local configuration, discover installed browsers, route URLs and launch the selected executable.

**Architecture:** A small Rust library under `src-tauri/core` compiles the backend modules independently of Tauri/WebView dependencies. Tauri owns a loaded configuration and exposes detection, route preview and launch commands. Existing specifications authorize this implementation; work proceeds inline.

**Tech stack:** Rust, serde, url, winreg (Windows only), tempfile, Tauri v2.

**Spec:** `SPECIFICATION.md` sections 2.2, 3.1 and milestone 2; builder skill phase 3.

## Constraints and decisions

- Windows 10/11; no runtime network connections or shell execution.
- Glob syntax only: `*`, `?`, host case insensitive, path case sensitive; ascending priority then id; fallback Firefox.
- Accept absolute HTTP(S) URLs. Reject executable-like input, credentials and other schemes before spawning.
- Config is `%APPDATA%/BrowserDock/config.json`. Generate a UUID token on first run; preserve unknown JSON fields and never replace malformed existing files with defaults.
- Registry discovery checks HKCU/HKLM and both registry views, followed by standard installation directories. Persist configured custom paths unchanged.
- Launch uses separate arguments, URL last; missing selected browsers return an error without switching browser identity.
- WebSocket dispatch and frontend interaction remain phases 4 and 7.
