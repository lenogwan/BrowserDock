# BrowserDock phases 4 and 5

**Goal:** Authenticated local tab focusing/opening with Chromium and Gecko companion builds.
**Spec:** SPECIFICATION.md sections 2.3, 4; builder phases 4–5. User authorized implementation of both phases.
**Architecture:** Extend the independently testable Rust library with a loopback WebSocket service and async dispatcher. Shared JavaScript companion source produces separate browser manifests and includes a local pairing options page.

## Protocol and decisions

- Bind 127.0.0.1 at configured ws_port; on address-in-use choose the next free port and persist it before serving. Never scan ports from the extension. Authentication token comes from settings.auth_token.
- Require AUTH within 5 seconds including handshake time; compare UUID token bytes in constant time. Registry is keyed by instance UUID, with an explicit browser ID; reject duplicate active IDs. Connection/message/queue limits bound memory.
- Add `{type:"AUTH_OK"}` acknowledgement and `{action:"PING"}` / `{action:"PONG"}` heartbeat. The extension sends heartbeats every 20 seconds; stale connections close.
- Keep authoritative FOCUS_OR_OPEN and response fields. match_mode is `domain_or_exact` (prefer exact URL, then hostname), `exact`, or `new_tab` (force new tab). HTTP(S) only, consistent with phase 3. Browser window_id is not a Win32 HWND and must never be passed as one.
- TABS_SYNC: at most 200 tabs, URLs at most 2048 UTF-8 bytes, titles at most 256 characters; snapshots no more often than 500 ms. Drop malformed input. No tab data logging or persistence.
- Dispatch only to the selected browser identity. Prefer an instance with cached matching tabs, otherwise one deterministic instance. Never broadcast an open request. No companion means process fallback; timeout after sending returns an error to avoid duplicate opens.
- Pairing options store explicit browser ID, token and port in extension local storage. No UA inference, remote code, telemetry, or externally accessible messaging.
- Chromium MV3 service worker and Gecko MV3 background scripts are distinct manifests. Reconnect timers plus alarms handle worker restarts. User installs unpacked builds manually; no external publishing.
